# Growth Playbook

Date: 2026-04-24

## Core Position

- Product: `inspection findings -> negotiation packet`
- Primary customer: `buyer agents and 2-10 seat buyer-agent teams`
- Secondary customer: `buyers under contract`
- Not the play: `broad homeowner repair SEO`, `inspection software replacement`, `generic AI parser`

## v1 / v2 Context

v1 was the broad repair-cost pSEO version: city, era, and component surfaces tried to discover traffic first and clarify product value later.

v1 failed because it produced generic repair-cost identity without enough live transaction intent. Search visibility could improve while users still did not understand LifeVerdict as a tool for a specific buyer-agent job.

v2 is the inspection ask pre-send check: one narrow transaction wedge with multiple high-intent entry surfaces. The surface can expand, but only around distinct transaction decisions that lead into the same packet workflow.

The operating rule is:

`narrow wedge, wider surface, same tool`

## Biggest Constraint

The current bottleneck is acquisition, not packet sophistication.

That means the operating question is:

`Which search surface brings in the right buyer-agent problem, gets the click, keeps the promise after the click, and leads to pre-send checks, revised packet use, or team-setup intent?`

## Search Surface Portfolio

Keep one core product and multiple high-intent entry surfaces around the same transaction moment:

Target portfolio size: `40 indexable tool-first surfaces`.

Core surfaces:

- `inspection response letter`
- `seller credit after home inspection`
- `repair request vs seller credit after inspection`
- `what to ask for after home inspection`
- `repair request after home inspection`
- `inspection objection after home inspection`
- `inspection contingency deadline after home inspection`

Expansion clusters:

- Counter / refusal: seller refused, seller counter, won't negotiate, fallback, reduce ask, rejected addendum, response to counter
- Scope / reasonableness: reasonable requests, what not to ask, how much credit, negotiation checklist, request list, report negotiation tool
- Financing: FHA, VA, lender-required repairs, appraisal-required repairs, seller-credit limits
- Form / deadline: repair addendum, repair amendment, contingency removal, resolution deadline, objection notice
- System-specific high intent: roof, sewer, electrical, foundation, mold, HVAC, plumbing leak, water intrusion, polybutylene, Federal Pacific panel

Each page should answer a different search phrasing but converge on the same packet workflow.

The expansion rule is narrow: add pages only when the query represents a real transaction decision, not a new informational blog category. `repair vs credit` and `deadline` pass that test because they change the user's next action inside the same inspection-response workflow.

## Money-Nearest Page Priorities

Business priority is not the same as search volume. Prioritize pages where the visitor is closest to a live file, lender risk, deadline risk, or second-round negotiation. Those are the moments where a buyer agent, team lead, or transaction coordinator is most likely to trust a tool if the output is specific.

1. `/seller-credit-limits-after-home-inspection` - money-nearest because bad credit structure can waste concessions, delay loan documents, or force last-minute restructuring.
2. `/fha-inspection-repairs-seller-credit` - money-nearest because repair-versus-credit framing can become a lender/appraisal blocker on government-loan files.
3. `/va-inspection-repairs-seller-credit` - money-nearest for the same reason, with stricter safety/property-condition sensitivity.
4. `/repair-request-vs-seller-credit-after-inspection` - core decision page. It owns the "what should we send" moment before the ask becomes a form or email.
5. `/seller-credit-after-home-inspection` - broadest money page. It should convert buyers, but its real value is qualifying agent/team repeat use.
6. `/lender-required-repairs-after-inspection` - deal-risk page. It should make lender-confirmation gates visible before users over-promise a credit.
7. `/seller-counter-offer-after-home-inspection` - second-round negotiation page. The user already has seller response data and needs a revised packet.
8. `/seller-refused-repairs-after-inspection` - crisis page. The user needs accept, walk, narrow fallback, or escalate evidence now.
9. `/inspection-contingency-deadline-after-home-inspection` - deadline page. The strongest value is preventing a buyer from losing leverage while waiting for perfect evidence.
10. `/roof-repair-credit-after-inspection` - first system-specific page to harden because roof issues are high-ticket, quote-sensitive, and often intersect lender/appraisal concerns.

Next in line after the top 10: `/sewer-scope-seller-credit-after-inspection`, `/inspection-objection-notice`, `/inspection-objection-after-home-inspection`, `/foundation-repair-credit-after-inspection`, and `/appraisal-required-repairs-after-inspection`.

## Top 10 Sample-Case Angles To Encode

Each priority surface should include one concrete sample case above the fold or immediately below the tool preview. The goal is to prove the page is not a rewritten article and that the tool understands the live transaction moment.

1. Seller credit limits: buyer asks for `$18,000` credit on a financed purchase, but estimated closing costs are only `$11,000`. Output should flag unused-credit risk, lender-confirmation needed, and a cleaner fallback structure.
2. FHA repairs: FHA buyer finds peeling exterior paint on an older home, missing handrail, and active roof leak. Seller offers credit only. Output should separate likely lender-required repair gates from negotiable credit items and mark final lender/form review.
3. VA repairs: VA buyer has exposed wiring, wood rot near steps, and seller suggests post-close credit. Output should flag safety/property-condition review, avoid guaranteeing VA eligibility, and produce a repair-first ask plus credit fallback for non-required items.
4. Credit vs repair: inspection shows active plumbing leak, old HVAC with no failed function, and several cosmetic defects. Output should lead with repair or licensed evaluation for the active leak, quote-needed status for HVAC, and cut cosmetic noise.
5. Seller credit: buyer agent drafts a `$15,000` credit request from roof, HVAC, and minor punch-list items. Output should label quote-backed versus estimate-only items, recommend a narrower first ask, and produce a lower fallback.
6. Lender-required repairs: appraiser or lender flags roof remaining-life concern after the inspection packet is drafted. Output should pause credit-only language, add lender-confirmation and completion-proof gates, and keep non-lender items in a separate fallback.
7. Seller counter: seller counters a `$12,000` ask with `$3,000` and one GFCI repair. Output should accept usable concessions, counter only the strongest quoted item, and remove low-leverage extras from the second response.
8. Seller refused: seller says "as-is, no repairs" after active water intrusion and sewer-scope concern. Output should present accept-as-is, walk, and narrow fallback paths, with evidence/disclosure pressure explained without legal overclaiming.
9. Inspection deadline: objection/inspection deadline is tomorrow night and the buyer is waiting on a contractor quote. Output should decide whether to send a narrow protected ask now, what evidence is missing, and what should not be added under deadline pressure.
10. Roof credit: inspector notes active roof leak and limited remaining life, contractor quote is `$8,200`, and buyer wants a `$12,000` credit. Output should anchor to the quote, warn on lender/appraisal review, and propose a defensible ask plus fallback.

## What To Measure Weekly

### Search Console

- impressions by surface URL
- clicks by surface URL
- CTR by surface URL
- top queries per surface
- whether query mix is still broad homeowner noise or is converging on post-inspection negotiation language

### First-party Product Funnel

Track these in order:

1. `surface view`
2. `tool open`
3. `packet generated`
4. `copy / print`
5. `optional email`
6. `buyer-agent team setup request`

The last item is the money-nearest signal.

## Operating Rules

### Rule 1: Do not choose a surface winner on packet quality alone

A surface can produce strong packet activation after the click but still be weak at getting the right traffic.

Check:

- `surface view -> tool open`
- `tool open -> packet generated`
- `packet generated -> copy/print`
- `packet generated -> team setup`

### Rule 2: Preserve search intent after the click

If a user searched `inspection objection` and lands on the tool, the tool should still feel like an objection-oriented intake.

Do not reset every user into the same generic seller-credit story.

### Rule 3: Revenue intent matters more than vanity activation

For this product, the best search surface is not necessarily the one with the highest copy rate.

It is the one that attracts:

- buyer agents
- repeat deal handlers
- small teams with live files

### Rule 4: Keep the wedge narrow

Do not widen back into:

- home maintenance
- DIY
- broad repair-cost education
- generic homeowner budgeting

### Rule 5: Remove legacy by relevance, not nostalgia

Do not redirect broad city/era repair-cost pages into the new tool unless the old URL is semantically close to inspection negotiation. Keep unrelated legacy pSEO out of the sitemap and let hard-retired pages return `410/noindex` so the domain identity shifts toward one product.

## Review Cadence

Every 7 days:

1. pull Search Console by page and query
2. pull `/admin/p-seo/validation-signals`
3. compare:
   - top-of-funnel winner
   - packet-activation winner
   - buyer-agent team-setup winner
4. decide:
   - keep testing
   - promote a surface
   - kill a weak surface
   - sharpen the handoff copy

## Near-Term Focus

1. Make the tool landing preserve the originating surface language.
2. Track acquisition in first-party logs, not only in GA.
3. Attribute team-setup leads to the acquisition surface.
4. Push buyer-agent team messaging into discovery surfaces, not only result pages.
5. Use Search Console to judge ranking and query mix, but use first-party funnel data to judge business value.

## Kill Criteria

Kill or de-prioritize a surface if, over a meaningful window, it:

- gets impressions but poor CTR
- gets clicks but weak tool opens
- gets tool opens but poor pre-send-check generation
- gets pre-send-check generation but no buyer-agent intent
- attracts broad homeowner traffic that does not map to the packet workflow

## Missed-Gap Audit: 2026-04-24

Search Console is a pre-deploy baseline for the old public surface, not a verdict on the new product direction.

Last 90 days for `sc-domain:lifeverdict.com`:

- `23` clicks
- `7,456` impressions
- `0.308%` CTR
- `11.14` average position

The highest-impression queries are still mostly legacy repair-cost or component phrases such as `argon gas windows baton rouge`, `conventional water heaters flagstaff`, and `average home repair costs chicago older homes`. Because the current pivot has not been deployed yet, this should be read as the baseline we need to move away from, not evidence that the new tool-first pages failed.

What this changes:

- The new tool-first surfaces are necessary, but cannot be judged until after deployment, indexing, and recrawl. Judge them by page-level Search Console query mix after they are live, not by the current legacy query mix.
- Do not add broad repair content to chase impressions. That recreates the original failure mode.
- The strongest next SEO move is deployment, sitemap submission, URL inspection for the priority surfaces, and then recrawl monitoring. Do not evaluate the new acquisition identity before that cycle starts.
- The strongest product move is de-escalation quality. The 1,100-case corpus caught multiple false positives where weak items were promoted into the lead ask.
- The strongest business signal is still repeat buyer-agent behavior: generated packet -> copy/print -> team setup request.
